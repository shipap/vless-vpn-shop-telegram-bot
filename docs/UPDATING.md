# Обновление

[Развёртывание](DEPLOYMENT.md) · [Резервные копии](BACKUP_RESTORE.md)

Обновляйте локальный стенд отдельно от публичной установки. Для production требуется собственный проверенный операторский процесс; команда `run_local.py` обслуживает только изолированные базы.

`install_production_instance.py` предназначен для первичной подготовки пустой базы и отказывает при попытке обновить существующую установку. Не используйте его как команду обновления или восстановления. Его `admit` оставляет все capabilities и gates выключенными.

## До изменения

Сохраните ревизию исходников, lock-файлы, версии образов, конфигурацию экземпляра и текущую версию миграций. Создайте защищённую резервную копию и проверьте восстановление. Прочитайте новые миграции и изменения конфигурации до их применения.

Сначала проверьте обновление на синтетической базе или изолированной защищённой копии без внешних получателей и провайдеров. Не запускайте worker копии с production-токенами: восстановленная база может содержать задания доставки и финансовых операций.

## Локальная установка

Примеры ниже выполняются из корня приложения в уже подготовленном окружении. Остановите собственные локальные API/worker обычным завершением в их терминалах. Не используйте сохранённый когда-то PID для остановки процесса.

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
npm.cmd ci
.\.venv\Scripts\python.exe scripts/run_local.py migrate
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps --no-build-isolation -e .
npm ci
.venv/bin/python scripts/run_local.py migrate
npm run typecheck
npm test
npm run build
```

Python-проверки выбирайте по изменению; общий запуск описан в [установке](INSTALL_RU.md). PostgreSQL-наборы с общими advisory locks запускайте последовательно. Повторный bootstrap не является необходимым шагом каждого обновления и не заменяет миграции.

## Откат

Смена образа приложения безопасна только при совместимости со схемой после миграций. Не выполняйте `alembic downgrade` без разбора конкретной миграции. Не восстанавливайте старый дамп поверх базы, в которой уже появились новые покупки или изменения аккаунтов.

При сбое сохраните текущее состояние и доказательства, остановите зависимые изменения через свой проверенный операторский процесс, затем выберите совместимый образ или исправление вперёд. Восстановление исторической копии требует учёта более новой активности и отдельного решения владельца.

Production admission связывает разрешённые ресурсы с конфигурацией и исходниками. После обновления старый манифест может дать `production_source_changed`. Подготовьте и проверьте новый допуск; отключение проверки хеша не является способом обновления.

HTTPS runtime bundle является неизменяемым снимком первой установки. Renderer
не перезаписывает несовпадающие файлы и не обновляет работающие контейнеры.
Смена сертификата также не обновляет уже скопированный TLS-файл автоматически.
Не удаляйте исходные артефакты для обхода этих ограничений: обновление исходников,
допуска, bundle и TLS требует отдельного проверенного процесса с сохранением
предыдущего состояния и проверкой восстановления.
