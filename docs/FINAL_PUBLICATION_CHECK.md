# Итоговая проверка перед публикацией

Дата: 15 октября 2026 года. Область: только публичный исходный дистрибутив
VLESS VPN Shop. Приватная установка, серверы и реальные провайдеры не затрагиваются.

Рекомендация: **READY FOR RELEASE CANDIDATE** для публичного исходного ZIP.
Неустранённых блокеров в проверенном составе не выявлено. Все 20 воспроизводимых
ошибок доставки исправлены и повторно проверены, расширенные регрессии прошли.
Это рекомендация для предварительного выпуска с ограничениями ниже,
а не подтверждение готовности произвольной production-установки.

для bootstrap также закреплён pip 26.2.1 вместо уязвимого pip 25.0.1 базового Python.

установки RU/EN. Рабочие зависимости и lock-файлы не требовали обновления.

## Проверка уязвимостей

Использованы npm audit 12.2.0 и [официальный pip-audit 2.10.1](https://pypi.org/project/pip-audit/),
установленный с PyPI в отдельную чистую venv. Пакеты приложения проверены по всем
66 точным записям `requirements.lock`, дополнительно проверены три build-пина,
включая установщик pip, который не входит в runtime lock-файл.
`--no-deps --disable-pip` проверяет полный уже закреплённый список без повторного
разрешения; `pip check` отдельно проверяет целостность установленного окружения.
Исключения конкретных CVE и автоматическое исправление с `--force` не применялись.

Начальный `pytest` без подготовленных ресурсов завершился с 33 FAIL, 56 ERROR,
2015 PASS, 1354 SKIP и 12 subtests PASS. По XML ошибки относились к отсутствующим
Git и явному тестовому DSN. Затем подготовлены официальный MinGit с проверенным
upstream SHA-256, новая PostgreSQL 17.11 и эмулятор Redis из fakeredis 2.39.0.
Источники и тесты распакованы в отдельную локальную копию.

Собственные тестовые серверы слушают только IPv6 loopback. Для тестовых процессов
адреса двух тестовых портов направлены на них; libpq использует `PGHOSTADDR=::1`.
Это не проверка настоящего сервера Redis. Существующие службы по IPv4 не
используются. Защиты приложения и проверки допустимых тестовых ресурсов сохранены.
PostgreSQL-наборы выполняются последовательно, в собственных временных схемах.

Для честной проверки восстановления исправлены именно условия стенда:
отдельный непривилегированный runtime, административная роль, собственный файл
ресурсов для backup tools, синтетический ключ приложения и ожидаемый тестами
адрес подключения. Изменения не переносились в рабочие конфигурации.
Из первых 97 падений после этого ушли 77. Оставшиеся 20 воспроизводились с
одной причиной: `_action_links()` вызывал `.rstrip()` у `dashboard_url=None`.
Это допустимая нейтральная конфигурация, поэтому отсутствие необязательных
кнопок не должно блокировать само уведомление.

Исправление проверяет тип необязательного адреса до построения кнопок.
Проверенные checkout-ссылки сохраняются; проверки URL, получателей, ролей и
повторной авторизации перед SMTP/Telegram отправкой не изменены. Сначала
новые тесты воспроизвели ошибку, затем прошли. В диагностике использовались
только синтетические данные и перехваченные исключения без секретов.

Полный набор после этой локальной правки повторно не запускался: повторены все
20 остававшихся падений и расширенный набор из 2228 тестов, включая положительные
и отрицательные сценарии уведомлений и повторной проверки полномочий. Это
отдельные реальные прогоны, а не утверждение, что исходный полный прогон был зелёным.
Пять пропусков: три проверки частного enclosing workspace неприменимы к клону,
два symlink-теста не смогли создать ссылки на Windows. Единственное предупреждение:
Starlette сообщает о будущем переходе TestClient с httpx на httpx2. Это не находка
уязвимости и не ошибка текущих тестов; закреплённые зависимости сохранены.
