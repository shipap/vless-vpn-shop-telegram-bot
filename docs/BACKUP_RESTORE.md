# Резервные копии и восстановление

[Обновление](UPDATING.md) · [Конфигурация](CONFIGURATION.md)

Резервная копия включает PostgreSQL, конфигурацию экземпляра, защищённые ключи и секреты, пользовательские медиа и сведения о версии исходников/миграций. Секреты храните отдельно от публичных материалов и вместе с копией только в защищённом хранилище. Дамп может содержать персональные данные и рабочие ссылки.

## Создать копию

Для своей установки используйте `pg_dump` совместимой версии и защищённый файл подключения PostgreSQL. Не вставляйте пароль в командную строку. Пример ниже требует настроенного libpq service `vpn_shop_backup` и закрытого каталога `.private/backups`; это имена примера, а не существующие настройки проекта.

```text
pg_dump --dbname=service=vpn_shop_backup --format=custom --no-owner --no-privileges --file=.private/backups/shop-before-update.dump
pg_restore --list .private/backups/shop-before-update.dump
```

Заранее проверьте, к какой базе относится service. Используйте новое имя файла для каждой копии, сохраните размер, SHA-256 и время создания. Проверка списка архива подтверждает читаемость оглавления; полноценная проверка требует восстановления.

PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .private/backups/shop-before-update.dump
```

Linux/macOS:

```bash
sha256sum .private/backups/shop-before-update.dump
```

В macOS без `sha256sum` используйте `shasum -a 256`. Сверьте хеш после переноса копии. Храните хотя бы одну копию отдельно от сервера с ограничением доступа и политикой хранения, выбранной владельцем.

## Проверить восстановление

Создайте отдельную пустую базу с отдельным пользователем, закрытую от runtime приложения. Настройте libpq service `vpn_shop_restore_check` именно на эту базу. Перед командой проверьте host, имя базы и отсутствие действующих подключений приложения. Не используйте service рабочей базы.

```text
pg_restore --dbname=service=vpn_shop_restore_check --single-transaction --exit-on-error --no-owner --no-privileges .private/backups/shop-before-update.dump
```

Не добавляйте `--clean` для восстановления в существующую рабочую базу. После восстановления проверьте версию миграций, таблицы, связи, последовательности, количество записей и финансовые итоги относительно сохранённого снимка. Не запускайте API, bot или worker восстановленной копии с внешними доступами.

Успешный код `pg_restore` сам по себе не подтверждает сохранность бизнес-данных. Сохраните отчёт проверки и точное назначение копии. Удаление проверочной базы выполняйте только после проверки её фактического имени, владельца и отсутствия активного использования.

## Возможности приложения

В коде есть задания резервного копирования, административный интерфейс и [проверка восстановления](../packages/infrastructure/src/sunrise_infrastructure/backup_verification.py). Их наличие не настраивает резервное копирование автоматически на новом сервере. Проверяющий компонент ограничен своим локальным контуром и создаёт отдельные проверочные ресурсы; это не универсальный production-оператор.

Для production настройте собственное расписание, закрытое хранилище, мониторинг и регулярную проверку восстановления. Ошибка отправки сообщения о копии не должна повторять финансовые операции. Отдельно проверяйте создание файла, его целостность, восстановление и доставку отчёта.
