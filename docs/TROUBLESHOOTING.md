# Решение проблем

[Установка](INSTALL_RU.md) · [Конфигурация](CONFIGURATION.md)

Сначала определите профиль: `.env.docker` обслуживает standalone Compose, `.env` обслуживает native-команды. Внешние переменные процесса могут перекрывать `.env`. Не выводите всю конфигурацию для диагностики: она содержит секреты.

| Симптом | Что проверить |
| --- | --- |
| `python` открывает Microsoft Store | Используйте `py -3.12` для создания venv, затем явный `.\.venv\Scripts\python.exe` |
| PowerShell запрещает `npm.ps1` | Используйте `npm.cmd`; изменение глобальной execution policy не требуется |
| Docker CLI есть, Server недоступен | Запустите Docker Desktop, выберите Linux containers, завершите требуемую перезагрузку WSL/Windows и повторите `docker version` |
| Порт занят | На первом `prepare` используйте другие `--landing-port` / `--dashboard-port`; существующая `.env.docker` автоматически не меняется |
| `prepare` отказывает по пути или ignore-правилам | Запускайте из обычного каталога без symlink/reparse-секретов; восстановите исключения `.env.*` в Git/Docker |
| API не стартует после `up` | Проверьте `init`: миграции и bootstrap должны завершиться с кодом `0`; затем проверьте PostgreSQL и Redis |
| Ошибка подключения к БД native | Сверьте loopback `55439`, разрешённое имя базы, драйвер `postgresql+psycopg`, пароль и URL-экранирование |
| Код входа не приходит в Docker | По умолчанию allowlist пустой и доставка отключена. Используйте отдельно настроенный синтетический native-профиль |
| В native-профиле нет письма | Проверьте свой адрес `.test`, `SUNRISE_EMAIL_ALLOWLIST` и закрытый каталог `SUNRISE_MAIL_DIR` |
| Код входа отвергнут или повторная отправка недоступна | Действует лимит попыток и серверный интервал 120 секунд; не обходите счётчики изменением frontend |
| Административная страница даёт 404 | Проверьте подтверждённую Telegram-идентичность, канонический аккаунт, owner/admin allowlist, роль и MFA |
| `legal_documents_invalid` | Нужны обе ссылки HTTPS, типы offer/privacy и непустые версии; текущие документы сохраняются в базе |
| Покупка или провайдер недоступен | Локальный профиль отключает внешние операции; production требует самостоятельного admission и разрешения конкретной возможности |
| `production_admission_missing` / `production_source_changed` | Текущий допуск отсутствует или не соответствует файлам. Нужен проверенный операторский процесс; не отключайте guard |
| Счёт имеет неизвестный исход | Сохраните заказ и операцию. GET-сверка должна найти однозначный результат; не создавайте повторный счёт вручную ради устранения предупреждения |
| PostgreSQL-тесты пропущены | Не заданы отдельные тестовые DSN/сервисы; это NOT RUN для зависимых интеграций |
| PostgreSQL-тесты зависают параллельно | Запускайте наборы последовательно: разные схемы не изолируют общие advisory locks |

## Локальная диагностика Docker

```text
docker compose --env-file .env.docker -f infra/compose.standalone.json ps -a
docker compose --env-file .env.docker -f infra/compose.standalone.json logs --tail 80 init api worker
```

Просматривайте вывод локально. Перед передачей отчёта удалите секреты, одноразовые коды, адреса клиентов, Telegram ID и рабочие ссылки. Не публикуйте `.env.docker`, полное `docker inspect` или раскрытый `docker compose config`.

Сообщение об ошибке должно содержать профиль, ревизию, операционную систему, команду без секретов, ожидаемый результат и обезличенный фрагмент ошибки. Не удаляйте тома, не сбрасывайте базу и не заменяйте владельца ради диагностики.
